# CAN sniffer — этап 5: встроенное Web-приложение

## Размещение

- исходники standalone TypeScript SPA: `Web/src`;
- сценарий воспроизводимой сборки: `Web/scripts/build.mjs`;
- локальные артефакты: `Web/dist` (не добавляются в Git);
- готовый образ Web-раздела QSPI: `Web/dist/qspi-web.bin`;
- физический диапазон Web-раздела QSPI: `0x000000..0x0FFFFF` (1 МиБ);
- memory-mapped адрес при прошивке: `0x90000000`.

Последние два subsector QSPI (`0xFFE000..0xFFFFFF`) по-прежнему используются
двумя чередующимися копиями настроек. Доступ к QSPI сериализован общим mutex в
`qspi_store.c`, поэтому чтение Web-ресурсов не пересекается с записью настроек.

## Сборка ресурсов

```powershell
cd CAN_sniffer/Web
pnpm install
pnpm build
```

Сборка создаёт `index.html`, JS и CSS, сжимает каждый ресурс gzip и упаковывает
их в `qspi-web.bin` с небольшой таблицей ресурсов, CRC32 и build ID. JS/CSS
получают content hash в имени. Сервер отдаёт:

- `index.html`: `Cache-Control: no-cache`;
- hash-ресурсы: `Cache-Control: public, max-age=31536000, immutable`;
- все ресурсы: `ETag`, `Content-Encoding: gzip`, точный `Content-Length` и
  `X-Content-Type-Options: nosniff`;
- совпавший `If-None-Match`: `304 Not Modified`.

В RAM одновременно находится не более 1 КиБ тела статического ответа и таблица
ресурсов. Сервер не распаковывает ресурсы на MCU.

## Интерфейс

SPA содержит четыре адаптивных раздела:

1. Live-поток CAN с фильтрами, сортировкой, паузой и виртуализированной таблицей.
2. Ноды CANopen и статистика/события/SDO-объекты выбранной ноды.
3. Завершённые `.CSL`-логи с прямым скачиванием.
4. Настройки Ethernet, Classic CAN и logger.

WebSocket-пакеты применяются к модели пачками с частотой не выше 10 Гц. Клиент
проверяет magic, версию, длину и sequence, автоматически переподключается и
показывает число потерянных кадров и отдельных разрывов sequence. CANopen
декодируется по тем же predefined connection set правилам, что локальный GUI;
для индексированных SDO показываются index/subindex, PDO mapping не выполняется.

## Дополнение API

Добавлены endpoints управления logger:

| Метод | Путь | Назначение |
|---|---|---|
| GET, PUT | `/api/v1/config/logger` | режим `full`/`selected` и выбранные ноды без запуска записи |
| POST | `/api/v1/logger/start` | начать запись с текущими настройками |
| POST | `/api/v1/logger/stop` | завершить текущий файл и остановить запись |
| POST | `/api/v1/statistics/reset` | сбросить счётчики CAN, анализатора, logger и API-потока |

```json
{
  "mode": "selected",
  "recording": false,
  "active_mode": "off",
  "selected_nodes": [1, 7, 42]
}
```

Допустимые режимы конфигурации: `full`, `selected`. Фактическое состояние
возвращается в `recording` и `active_mode`; ответ также содержит `card_state`,
имя и размер текущего файла, свободное место, счётчики сохранённых/потерянных
кадров, ошибок записи и восстановлений. Изменение конфигурации во время записи применяется к logger,
но само по себе не запускает и не останавливает её. Сетевые и CAN-настройки
продолжают сохраняться в QSPI.

Список нод содержит время последнего кадра, долю трафика и раздельные счётчики
SDO (`abort`, `timeout`, `protocol`, `orphan`, `conflict`). Снимки событий также
возвращают CAN ID/формат, задержку ответа, DLC и байты данных — те же поля,
которые доступны на локальном дисплее.
