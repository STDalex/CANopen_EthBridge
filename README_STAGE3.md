# CAN sniffer — этап 3: запись на microSD

## Реализовано

- режимы `Off`, `Full` и `Selected nodes`; в каждый момент существует только
  один поток дампа;
- выбор обнаруженных CANopen-нод касанием номера на экране `Nodes`; выбранные
  строки отмечаются `*`;
- исходные Standard/Extended Data/Remote Classic CAN кадры и непрерывная
  64-битная шкала времени в версионированном бинарном формате `.CSL`;
- блоки до 64 КиБ с sequence number, CRC заголовка и CRC payload;
- фиксированный staging-пул 2 МиБ во внешней SDRAM и очередь указателей;
- отдельная `Storage task` — единственный владелец FatFs и SDMMC1;
- многосекторные SDMMC/DMA-записи с D-cache maintenance, короткими повторами
  сбойной операции, попытка предварительного непрерывного выделения,
  `f_sync` каждые 2 секунды и ротация перед 32 МиБ;
- определение карты через PC13, повторное монтирование, обработка заполнения и
  ошибок записи без остановки CAN ISR/анализатора;
- при кратком сбое записи текущий 64-КиБ блок остаётся во владении
  `Storage task`, последующие блоки удерживаются в 2-МиБ staging-пуле и
  записываются по порядку после восстановления карты;
- восстановление `.TMP` до последнего целого блока и сохранение файлов с
  повреждённым заголовком как `.BAD`;
- отдельные счётчики сохранённых и потерянных кадров, ошибок записи и
  восстановлений, а REST API дополнительно сообщает число буферизованных
  блоков, повторы SD I/O, адрес последнего сбойного сектора, HAL/SDMMC-коды и
  максимальную длительность чтения/записи;
- экран `microSD Log`: состояние карты, режим, имя и размер файла, свободное
  место, ошибки, потерянные кадры и число выбранных нод;
- `SESSION.JSON` с читаемыми метаданными;
- dependency-free host-конвертер в CSV, JSONL и candump-подобный текст.

Текущая версия ПО: **3.0.0**.

## Подготовка карты

Рекомендуется microSD 8–32 ГБ с одним primary-разделом MBR, FAT32 и кластером
32 КБ. Прошивка карту не форматирует и не переразбивает. exFAT не поддерживается.

Структура данных:

```text
/CANSNIFF/LOGS/S000001/
    SESSION.JSON
    L000001.CSL
    L000002.CSL
```

Активный файл имеет расширение `.TMP`. После штатного закрытия или
восстановления он становится `.CSL`.

## Расширение функционала

FatFs и SDMMC принадлежат только `Storage task`. Если будущей функции тоже
понадобится microSD, она должна передавать запрос этому потоку через отдельный
тип сообщения в очереди; прямые вызовы FatFs из GUI, CAN ISR или анализатора не
допускаются. Так новые функции смогут совместно использовать тот же раздел и
каталоги, не повреждая активный дамп и не задерживая приём CAN.

## Сборка и проверка

Открыть `MDK-ARM/CAN_sniffer.uvprojx` и собрать target `CAN_sniffer` Arm
Compiler 6.19. Host-side тесты запускаются командой:

```text
python -m unittest discover -s tests -p "test_*.py" -v
```

Полная спецификация находится в `doc/CAN_SNIFF_LOG_FORMAT.md`.
