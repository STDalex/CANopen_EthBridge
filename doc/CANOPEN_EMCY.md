# Диагностика CANopen EMCY

EMCY (Emergency) — асинхронное аварийное сообщение, которое формирует само
CANopen-устройство. Оно не является HTTP-ошибкой Bridge и не обязательно
означает неисправность CAN-линии.

## Формат кадра

Стандартный COB-ID имеет вид `0x080 + Node ID`. Для Node 2 это `0x082`.
Классический EMCY всегда содержит 8 байт:

| Байты | Назначение |
|---|---|
| 0…1 | 16-битный Emergency Error Code, little-endian |
| 2 | Error Register, объект `0x1001` |
| 3…7 | диагностические данные производителя |

Код `0x0000` означает `Error reset / No error`: устройство сообщает, что
ранее объявленное аварийное состояние снято.

## Пример Baumer IVO GBAM

Устройство с Identity Object `0x1018`:

- Vendor ID `0x000000EC` — Baumer IVO;
- Product Code `0x0000000F`;
- Device Name `GBAM`;
- Device Type `0x00010196` — абсолютный однооборотный энкодер CiA 406;
- аппаратная версия `1.00`, программная версия `1.15`.

Аварийное сообщение:

```text
CAN-ID 0x082  DLC 8  DATA 20 73 01 01 00 00 00 00
```

Расшифровка:

| Поле | Значение | Смысл |
|---|---:|---|
| Error Code | `0x7320` | Position error |
| Error Register | `0x01` | Generic error |
| Alarms `0x6503` | `0x0001` | Position error active |
| Warnings `0x6505` | `0x0000` | предупреждений нет |

Если вслед за ним приходит кадр `00 00 01 00 00 00 00 00`, код `0x0000`
сообщает о восстановлении измерения. PDO, полученное во время активного
`Position error`, следует считать потенциально недостоверным.

Для этой серии энкодеров `0x7320` относится к измерению позиции, а не к CAN.
Ошибки контроллера или контроля соединения обычно имеют коды `0x81xx`.

## Что проверять

1. Повторить испытание при медленном равномерном вращении.
2. Постепенно повышать известную скорость и определить порог появления EMCY.
3. Проверить допустимую частоту вращения по точному заказному номеру датчика.
4. Проверить питание непосредственно на разъёме энкодера, общую землю и
   отсутствие кратковременных провалов.
5. Проверить муфту, люфт, радиальное биение и ударные нагрузки на вал.
6. Уменьшить период TPDO: редкий PDO не позволяет определить пиковую скорость
   и может скрывать полный оборот между соседними значениями.

Если ошибка появляется только при заведомо чрезмерной скорости и сразу
сбрасывается, это похоже на превышение динамических возможностей считывания.
Появление `0x7320` при медленном плавном движении указывает на проблему
механического сопряжения, питания или самого энкодера.

## Чтение диагностических объектов

Для SDO-чтения через REST API используется `POST /api/v1/can/tx`. Пример для
Error Register Node 2 в Windows PowerShell:

```powershell
$body = @{
  node_id = 2
  command = 'read'
  index = 0x1001
  subindex = 0
  timeout_ms = 200
} | ConvertTo-Json -Compress

Invoke-RestMethod -Method Post `
  -Uri 'http://192.168.1.7/api/v1/can/tx' `
  -ContentType 'application/json' `
  -Body $body
```

Полезные объекты:

| Объект | Назначение |
|---|---|
| `0x1001:0` | текущий Error Register |
| `0x1003:0` | количество сохранённых ошибок |
| `0x1003:1…8` | история, от новой записи к старой |
| `0x1018:1…4` | Vendor ID, Product Code, Revision, Serial Number |
| `0x6503:0` | alarms профиля энкодера |
| `0x6505:0` | warnings профиля энкодера |

Запись нуля в `0x1003:0` очищает историю устройства. Не выполняйте её до
сохранения диагностических данных.

Описание кодов и объектов для рассматриваемого семейства приведено в
[руководстве Baumer IVO Absolute Encoder with CANopen](https://www.audin.fr/pdf/manuels/baumer/codeurs/Manuel_CANopen.pdf).
